= Scout Unit and Enemy Search Implementation

== Overview
This document describes the implementation of the Scout unit and the EnemySearcher system for AI reconnaissance.

== Components Added

*Unit Properties*:
* *Name:* Scout
* *Icon:* 🔦 (flashlight emoji, `UnitConstants.ts:97`)

=== 2. EnemySearcher Class (`src/game/engine/EnemySearcher.ts`)

A sophisticated enemy detection system using a hybrid search algorithm.

*Search Strategy*:
. *Spiral Search* - Prioritizes nearby enemies by searching outward in expanding square rings
. *Row-Major Fallback* - Ensures complete coverage by scanning remaining tiles systematically

*Key Methods*:

==== `findNearestEnemy()`
[source,typescript]
----
public static findNearestEnemy(
  startCol: number,
  startRow: number,
  mapWidth: number,
  mapHeight: number,
  getUnitAt: (col: number, row: number) => any,
  getCityAt: (col: number, row: number) => any,
  isVisible: (col: number, row: number) => boolean,
  civilizationId: number,
  maxRadius?: number,
  isFriendlyCiv?: (civId: number) => boolean
): SearchResult | null
----

Returns the nearest enemy unit or city within visible range. The optional
`isFriendlyCiv` predicate treats locked teammate civs as friendly.

==== `findAllEnemiesInRadius()`
[source,typescript]
----
public static findAllEnemiesInRadius(
  startCol: number,
  startRow: number,
  mapWidth: number,
  mapHeight: number,
  getUnitAt: (col: number, row: number) => any,
  getCityAt: (col: number, row: number) => any,
  isVisible: (col: number, row: number) => boolean,
  civilizationId: number,
  maxRadius: number,
  isFriendlyCiv?: (civId: number) => boolean
): SearchResult[]
----

Returns all enemies within `maxRadius` (the 9th argument) of the start tile,
sorted by distance and priority.

*Search Result Interface*:
[source,typescript]
----
interface SearchResult {
  col: number;           // Enemy tile column
  row: number;           // Enemy tile row
  distance: number;      // Square distance from search origin
  targetType: 'unit' | 'city';  // Type of enemy found
  targetId: string;      // ID of the enemy unit/city
  priority: number;      // Higher = more important target
}
----

*Features*:
* Respects fog of war - only searches visible tiles
* Uses visited Set to avoid duplicate checks
* Optimized for medium-size maps (70x50)
* Detailed logging with statistics

=== 3. AI Scout Behavior (`src/game/engine/AI/AIManager.ts`)

*Scout Reconnaissance Flow* (the scout handling in `chooseAITarget` starts at
`AIManager.ts:5863+`):

. *Defense override first*
   ** Before scouting, the scout checks whether a friendly city nearby is
      undefended while an enemy is close (`findScoutDefenseTarget`) and
      garrisons it until the threat clears
. *Village detour*
   ** Before the enemy search, an unvisited village is collected if one is
      reachable (`findNearestVillage`), then reconnaissance resumes
. *Enemy Search Phase*
   ** Scout uses `EnemySearcher.findNearestEnemy()` to scan for enemies
   ** Searches only visible/explored tiles
   ** When an enemy is found, stores it in `unit.enemyFound` and
      `unit.enemyLocation`
. *Return to City Phase*
   ** Scout identifies nearest own city using `AIUtility.findNearestOwnCity()`
   ** Pathfinds back to the city
   ** Upon arrival the scout **clears `enemyFound` / `enemyLocation` and
      resumes reconnaissance** — there is no production switch and no
      `city.enemyTarget`; the flags are cleared precisely so the scout does not
      select its own city forever and starve the army's intelligence

*Helper methods*:

==== `AIUtility.findNearestOwnCity(unitCol, unitRow, unitCivilizationId, cities, squareDistance?)`
In `src/game/engine/AI/AIUtility.ts:359` — finds the closest city owned by the
unit's civilization using square distance calculation. (`triggerWarriorProduction`
does not exist anywhere in the codebase.)

*AI Production Changes*:
* Human cities: build a **Scout first** at population ≥ 1 when the civ has none
  (`AutoProduction` branches at `:864-875` and `:943-956`) — before further
  settlers
* AI cities: `GameEngine.pickInitialAIProduction` queues a scout first when the
  civ has none, then the cheapest defender for the first two cities, then a
  warrior

== Workflow

=== AI Turn Processing
. AI founds city → `pickInitialAIProduction` queues a Scout (once), then a defender/warrior
. Scout completes production → Deploys from city
. Scout explores map using standard exploration AI
. Scout uses EnemySearcher during each turn
. When enemy detected:
   ** Scout stores `unit.enemyFound` / `unit.enemyLocation`
   ** Scout pathfinds to nearest own city
   ** Scout clears both flags on arrival and resumes recon next turn

=== Key State Management
* `unit.enemyFound` (boolean) - Flag indicating scout found enemy
* `unit.enemyLocation` ({col, row}) - Stored enemy coordinates

(Cleared on arrival at the nearest own city; there is no `city.enemyTarget`.)

== Technical Details

=== Search Algorithm Performance
* *Spiral Search:* O(r²) where r is radius to enemy
* *Row-Major Fallback:* O(w×h) worst case where w=width, h=height
* *Early Exit:* Returns immediately upon finding nearest enemy
* *Visited Set:* Prevents redundant tile checks

=== Visibility Integration
* Uses tile.visible and tile.explored for visibility checks
* Scouts have enhanced sight range (2 tiles)
* EnemySearcher respects fog of war boundaries
* Only visible enemies can be detected

=== Logging Prefixes
* `[AI-SCOUT]` - Scout behavior and decisions
* `[EnemySearcher]` - Search progress and results

(There is no `[AI-CITY]` prefix — scout behaviour logs under `[AI-SCOUT]`.)
