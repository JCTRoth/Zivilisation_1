= Adding a new map

Everything needed to ship a new world: how to *make* one, how to wire it into
the game, how to make it a selectable scenario, and how to prove it is actually
a good map rather than a shape that merely loads.

Companion documents: `STATIC_MAPS.adoc` (the data format in depth) and
`../scripts/generate-naval-map.mjs` (the reference generator, with its own
in-file notes on why the archipelago is shaped the way it is).

== The two ways to make a map

[cols="1,3,2"]
|===
| Approach | When to use it | Cost

| **Static map file**
(`src/data/maps/*.json`)
| The layout must be *identical on every machine and every run*: a scenario, a
spectator map, a hand-designed puzzle, or anything extracted from Freeciv.
| Hand-write the data, or generate it with a script.
| One JSON file + registration.

| **Procedural generation**
(`MapGenerator`)
| Variety, and when the shape only needs to satisfy constraints rather than be
exact. Two players should not get the same world twice.
| Adjust the existing generator, or add a `generateX()` method.
| Code changes in `MapGenerator`; the size still has to be registered.
|===

Prefer a static map. Every scenario that is *supposed* to demonstrate something
— a naval AI, a doom stack, a specific island chain — has to be the same map
every time you run it, or the results are not comparable.

== The static map format

One JSON file per map, in `src/data/maps/`:

[source,json]
----
{
  "id": "my-map-64x48",              // stable id; also the file name
  "name": "My Map",                 // shown in the UI / logs
  "source": "generated by scripts/generate-my-map.mjs",
  "width": 64,
  "height": 48,
  "rows": [                         // ONE CHARACTER PER TILE, one string per row
    "   gghh    ...",               // exactly `width` characters
    ...
  ],
  "specials": [                     // optional: bonus-resource flags
    "0000000000...",                // exactly `height` strings
    ...
  ],
  "startPositions": [               // optional: fair spawns
    { "col": 12, "row": 20 },
    ...
  ]
}
----

=== Terrain characters (raw Freeciv 1.x)

The file keeps the *raw* characters so it stays a faithful copy of its source.
`FREECIV_TERRAIN_LEGEND` in `src/data/maps/types.ts` translates them at load
time.

[cols="1,1"]
|===
| Char | Terrain | | Char | Terrain
| `' '` | ocean | | `p` | plains
| `a` | arctic | | `g` | grassland
| `t` | tundra | | `f` | forest
| `d` | desert | | `j` | jungle
| `s` | swamp | | `h` | hills
| | | | `m` | mountains
|===

An unknown character is *not* an error at load time — it falls back to ocean.
That is why `validateStaticMap` exists and why the loop at the bottom of
`src/data/maps/index.ts` shouts at load time if a shipped map is malformed.
Run the validator yourself before committing.

=== What the loader adds, and what it does not

`MapGenerator.generateFromStatic` runs the static terrain through the same
pipeline as a procedural map, so these all still apply:

* `stage5_Rivers` — rivers are carved from *land* (the source map has none).
* `fillIsolatedOceanHoles` — one-tile ocean pockets become land.
* `classifyLakes` — an ocean body of ≤ `LAKE_MAX_TILES` (24) becomes a **lake**,
  which is impassable to everyone, ships included. A 96×60 archipelago has one
  3800-tile ocean body, so it stays ocean; a cramped map may surprise you.
* `stage7_FloodFillGroups` / `stage8_BuildSites` / `ensurePassability`.

Two things the file controls and the generator does *not*:

* **Bonus resources** come from the `specials` layer only. `'2'` (or any non-`'0'`)
  means "this tile has a bonus"; which bonus is decided by the terrain
  (`TERRAIN_RESOURCES`: hills → Coal, plains → Horses, desert → Oasis, …).
  Water is never flagged from a static file.
* **Everything else is re-rolled per game** from the seeded RNG, including which
  tiles are *ordinary* resources. The map is deterministic in *terrain* but not
  in *resources* unless you pin `mapSeed`. For a scenario whose difficulty must
  not vary, that matters.

[TIP]
====
*Resources are placed by terrain, so a `'2'` on grassland produces nothing*
(`TERRAIN_RESOURCES.grassland` is `null`) — wasted flags are silently dropped.
`tests/staticMaps.test.ts` asserts the opposite direction: every `'2'` on a
resource-bearing terrain *does* yield a resource.
====

=== Fish is coastal

Fish is the one resource with a placement rule: only on water that touches land
in the 8 surrounding tiles (lakes do not count as land). Open ocean gets none,
whatever the roll says. On the 96×60 archipelago that took the count from ~606
(~89 % of them hundreds of tiles from any shore, where no boat can work) to
~170, all of them hugging a coast. See `COASTAL_FISH_CHANCE` in
`src/data/TerrainConstants.ts` and `MapGenerator.isCoastalWater`.

Consequence for map design: *shoreline is the resource*. A map whose coasts are
short gives cities little to do; one with long, indented coasts gives a
Fisher Boat something worth building. A city also has to border water at all
(`cityHasHarborOrCoast`) and own a `harbor` building to build the boat.

== Registering the map

Five places. Missing one is the usual reason a new map "does not appear".

=== 1. The registry — `src/data/maps/index.ts`

[source,ts]
----
import myMap from './my-map-64x48.json';

export const STATIC_MAPS: Record<string, StaticMapDefinition> = {
  'earth-180x90': earth180x90 as StaticMapDefinition,
  'my-map-64x48': myMap as StaticMapDefinition,
};

/** Which static map backs a map type, if any. */
export const STATIC_MAP_FOR_MAP_TYPE: Readonly<Record<string, string>> = {
  EARTH: WORLD_MAP_ID,
  MY_MAP: 'my-map-64x48',           // ← new
};
----

=== 2. The map size — `GameEngine.generateWorld`

The generator is told how big the world is *before* it loads the map, and the
static loader fills anything outside the file with ocean. A size mismatch
therefore does not crash — it silently pads the map with water, which is a
confusing way to lose a third of your continent.

[source,ts]
----
} else if (mapType === 'MY_MAP') {
  // Static map (src/data/maps/my-map-64x48.json) — must match the static
  // map's dimensions so every tile of it is used.
  mapWidth = 64;
  mapHeight = 48;
  console.log(`[GameEngine] Using my map size for ${mapType}: ${mapWidth}x${mapHeight}`);
}
----

=== 3. The scenario in the setup screen — `src/components/ui/GameSetupModal.tsx`

[source,tsx]
----
<option value="MY_MAP">My Map · 64x48 two-continent strait</option>
----

The summary blurb underneath renders from `mapType`, so nothing else is needed.
Keep the label in the form *"Name · what makes it interesting"* — that is what
a player scans.

=== 4. Dev Mode, for spectator maps — `src/data/GameConstants.ts`

If the map is an AI-vs-AI scenario, add the type to `AUTO_SCENARIO_MAP_TYPES`.
That single list drives all of the unattended behaviour:

* Dev Mode is forced on (whole map observable, nothing waits for a human);
* the game gets an `aivsai-…` log session instead of `game-…`;
* no per-move sleeps, and no "Auto. turn ending" offer modal;
* the AI turn budget scales with the map (`aiTurnTimeoutMs`);
* the game auto-restarts after it concludes.

Do *not* add a new `mapType === '…'` check. That list used to be hardcoded in
seven places and drifted, which is why the naval maps were paying a 200 ms
sleep per move and never auto-ticked Dev Mode.

For a **human** map, Dev Mode stays off and the map is played normally.

=== 5. Production-profile rotation (AI-vs-AI only)

`GameEngine.createCivilizations` rotates the AI personalities by seed so batch
runs are not the same match-up every time. If you added the type to
`AUTO_SCENARIO_MAP_TYPES`, also include it in the `rotateProfiles` list there,
or slot 0 always plays the same personality.

== Making the map good, not just loadable

A map that generates is not a map that plays. These are the constraints that
actually decide whether a scenario works, learned the hard way on the naval
archipelago.

=== Every civ starts on its own island, on a coast

* One home island per civ. Two civs sharing a continent never need a fleet, and
  a naval AI scenario then never exercises its naval AI.
* Every start tile must be *coastal*. `civCanBuildShips` requires a city with
  water access, so a civ whose capital cannot see water can never research into
  a fleet, never colonise, never invade. The first cut of the naval map put 7
  of 8 starts inland and the whole naval game was dead on arrival.
* Home islands big enough to found an empire on. The generator comment is blunt
  about it: a civ on a 52-tile rock never gets past one city, never finishes
  Sailing, and never fields a ship, so no naval war can ever start. ~160–350
  tiles each.
* Channels wide enough that a ferry is required and a land unit is not.

=== Small islets, or colonisation is dead code

`getColonizableIslands` only offers landmasses of **≤ `SMALL_ISLAND_MAX_TILES`
(24 tiles)**, that no civ has settled, that the civ has seen, and that have an
adjacent ocean tile. A map of only large islands can never satisfy that, so the
entire ferry-a-settler-to-an-island feature is unreachable — a 417-round game
produced **zero** colony missions and 60 land-only cities.

The naval map now carries 8 home islands (160–351 tiles) plus 10 islets of 17
tiles in the channels, each with a guaranteed water gap so it is its own
landmass. Keep the islets a comfortable margin below the 24 cap, and do not let
one touch a home island or it stops being an islet.

=== A water gap between every pair of islands

Checked in `tests/navalArchipelagoMap.test.ts` ("leaves a sea channel between
every pair of islands"): two landmasses that share an edge are one landmass, so
a single-tile channel silently welds your scenario into a continent. Also beware
the polar rows — a full-width ice cap is one enormous landmass that connects the
top and bottom of the map.

== Generating a map with a script

`scripts/generate-naval-map.mjs` is the reference. Its shape:

[source,js]
----
/** Deterministic PRNG so the map is byte-identical on every regeneration. */
function mulberry32(seed) { /* … */ }
const rng = mulberry32(0x5eaf00d);

// 1. Draw terrain into `rows` / `specials` (string art).
// 2. Stamp small islets into the open water, each with a water gap.
// 3. Pick a start position per island: passable AND coastal.
// 4. VERIFY the shape, and refuse to write the file if it is wrong.
const comps = landmasses();
if (colonisable.length < ISLET_TARGET) errors.push(/* … */);
if (errors.length) { console.error('MAP REJECTED'); process.exit(1); }
writeFileSync(resolve(OUT_DIR, `${MAP_ID}.json`), JSON.stringify(map, null, 1));
----

Non-negotiables:

* **Seeded PRNG.** The file must be byte-identical on every regeneration, or
  "just regenerate" becomes an unreviewable diff of 60 rows.
* **Verify, then write.** The script exits non-zero rather than shipping a map
  that violates its own design. The archipelago check that matters most: home
  islands ≥ the empire threshold, islets ≤ the colonisation cap, a water channel
  between every pair, one coastal start per island.
* **Take the output id as an argument** (`node scripts/generate-naval-map.mjs
  naval-archipelago-tropical-96x60`) so one script can produce variants.

== Verifying a new map

=== Fast, no browser

[source,bash]
----
# 1. Does it validate, and is the shape what you intended?
npx vitest run tests/navalArchipelagoMap.test.ts --no-file-parallelism

# 2. Does it load, and what does the generator make of it?
npx vitest run tests/staticMaps.test.ts --no-file-parallelism
----

=== Play it, unattended

The naval scenario runner is headless — no browser, no clicks, and it writes a
CSV you can diff between runs:

[source,bash]
----
node scripts/run-naval-session.mjs 200 12 4     # rounds seed civs
----

For a browser spectator session, the URL route launches the scenario with no
setup wizard at all:

[source,bash]
----
# ?maptype=AI_VS_AI_NAVAL&civs=7&seed=123&gold=50&noanim
----

=== Look at the numbers, not just the screenshot

A 200-round run's CSV (`doc/GAME_PROGRESSION_EXPORT.adoc`) answers the questions
that decide whether a map is good:

[cols="1,3"]
|===
| Column | What a healthy map looks like
| `citiesFounded` | growing steadily; a map nobody can expand on stays flat
| `stalls` / `noPath` | near zero. High numbers mean unreachable targets
| `unitsLost` vs `units` | a sane ratio. A map where the AI shreds units is a trap
| `aiActions` | many small numbers, no single huge one (that is a stall loop)
| `warWith` | non-empty by mid-game on a scenario meant to have a war
|===

Two failure signatures worth recognising:

* **A map nobody can reach** — no attacks, no wars, both sides trading
  declarations forever. The strait is too wide or the starts are wrong.
* **A map nobody leaves** — high city counts, zero naval units. There is nothing
  across the water worth crossing to.

== Tests to add with the map

A map-specific test is what stops a regeneration from silently undoing its
design. `tests/navalArchipelagoMap.test.ts` is the model — it pins the
*invariants*, not the pixel counts:

* the file validates (`validateStaticMap` returns no errors);
* it splits into real islands, home islands above the empire threshold;
* ≥ 4 islets at or below the colonisation cap, each with a landing tile and no
  mountains (a settler must be able to found a city on it);
* ≥ 4 start positions, each on a *different* island and each coastal;
* a water channel between every pair of islands.

Asserting the exact landmass count is tempting and wrong: a regeneration that
improves the coastlines should not need the test rewritten.

Register it alongside the existing ones so the suite is the map's real spec.

== Checklist

. Map file in `src/data/maps/`, `rows` exactly `width` chars, `specials`
  exactly `height` strings, only known terrain characters
. Registered in `STATIC_MAPS` and `STATIC_MAP_FOR_MAP_TYPE`
. Map size added in `GameEngine.generateWorld`, matching the file exactly
. Option added in `GameSetupModal` with a "Name · why it is interesting" label
. AI-vs-AI only: type added to `AUTO_SCENARIO_MAP_TYPES` and to
  `rotateProfiles`
. Every start coastal, one home island per civ, home islands big enough to
  found an empire
. Small islets present and ≤ `SMALL_ISLAND_MAX_TILES`, separated by water
. Map-specific test asserting the invariants
. `npx tsc --noEmit` and `npm run lint` clean
. A 200-round headless run with a sane progression CSV
