= GoToManager Implementation

== Overview
The `GoToManager` class has been created to centralize all "Go To" movement functionality in the Civilization game. This class handles pathfinding, path execution, and automatic unit movement along calculated routes.

== File Location
`src/game/engine/GoToManager.ts`

== Key Features

=== 1. *Path Calculation*
* `calculatePath(unit, targetCol, targetRow, getTileAt, mapWidth, mapHeight)` - Calculates optimal path from unit's current position to destination
* Uses the existing `Pathfinding` class for route calculation
* Returns success status and calculated path array

=== 2. *Path Management*
* `setUnitPath(unitId, path)` - Sets a Go To path for a unit and syncs with RoundManager
* `getUnitPath(unitId)` - Retrieves the current path for a unit
* `clearUnitPath(unitId)` - Clears the path and syncs with RoundManager
* `getAllUnitPaths()` - Returns all active unit paths
* `hasPath(unitId)` - Checks if a unit has an active Go To path

=== 3. *Path Execution*
* `executeFirstStep(unitId)` - Executes the first step of a unit's path
** Checks for valid path and unit state
** Validates unit has moves remaining
** Calls GameEngine's moveUnit method
** Updates path after successful move
** Returns success status, reason, and remaining path

* `executePathWithAnimation(unitId, delayMs, onStepComplete)` - Executes entire path with animation
** Async method that moves unit step-by-step
** Includes configurable delay between moves for animation
** Calls callback after each step for UI updates
** Automatically stops when path is complete or unit runs out of moves
** Returns total steps completed

=== 4. *Cleanup*
* `cleanupDestroyedUnits(existingUnitIds)` - Removes paths for units that no longer exist

== Integration Points

=== GameEngine
* GoToManager instance created in constructor: `this.goToManager = new GoToManager(this, this.roundManager)`
* Available as `gameEngine.goToManager`

=== GameCanvas
The following sections have been updated to use GoToManager:

. *Go To Mode Click Handler* (lines ~650-740)
** Uses `goToManager.calculatePath()` to find route
** Uses `goToManager.setUnitPath()` to set the path
** Uses `goToManager.executeFirstStep()` for initial move

. *Unit Click Path Continuation* (lines ~780-800)
** Uses `goToManager.hasPath()` to check for existing path
** Uses `goToManager.executeFirstStep()` to continue movement

. *Automated Path Execution* (lines ~880-1050)
** Uses `goToManager.setUnitPath()` to set path
** Uses `goToManager.executePathWithAnimation()` for smooth animated movement
** Includes fallback to old method if GoToManager unavailable

=== RoundManager
* RoundManager maintains its own path storage for compatibility
* GoToManager syncs paths with RoundManager automatically
* RoundManager still processes automated movements at turn start

=== GoTo Camera Rule (black-screen refocus)
After a route has been assigned (`assignUnitPath` in GameCanvas), the camera
comes back to the unit that received the order — but only when the screen is
more than 80% black at that moment. That happens when the player panned out
into unexplored space to plot the destination; a black screen shows nothing,
so the view returns to the unit that will walk the route (which is also where
the route is actually drawn). A viewport that still shows real map content —
the route, the destination, own territory — stays exactly where the player
put it.

* `src/utils/ViewportBlackCoverage.ts` computes the black share of the
  viewport: unexplored tiles plus off-map space, matching what the renderer
  paints black (explored-but-fogged tiles are dimmed, not black, and are not
  counted). `BLACK_COVERAGE_REFOCUS_THRESHOLD` is `0.8`.
* `useGameStore().actions.focusGoToUnitIfBlind(col, row)` applies the rule at
  route-assignment time. It delegates to `focusCameraOnTile`, so the pan uses
  the usual camera glide and honors the player's autoCamera setting.
* The rule lives at the UI call site, not inside `GoToManager`: engine/AI path
  assignments must never move the human's camera.

=== Unit Edge-Follow (camera nudges along while a unit moves)
While a unit is gliding, the render loop watches its interpolated display tile.
When the tile reaches the viewport's edge margin (half a tile), the camera
shifts by just the overrun, in the unit's direction — the unit stays fully
visible and the camera follows it step by step instead of re-centering. A unit
that walks far (a long GoTo route, a queued march) therefore drags the view
along with it.

* `nudgeCameraToKeepPointInView` in `src/utils/CameraUtils.ts` is the pure
  geometry: it compensates only the overrun, never overshoots, and clamps to
  the map bounds with `clampCameraToMap`. `EDGE_FOLLOW_MARGIN_TILES` is `0.5`.
* `useGameStore().actions.followMovingUnit(unitId, displayCol, displayRow)` is
  called from the GameCanvas render loop for every active glide. It applies the
  same followability rule as `focusOnNextUnit` (own units, or foreign units the
  human can currently see; dev mode overrides) and honors `autoCamera`.
* Hidden AI movement is never trailed, AI-vs-AI runs never pan, and the nudge
  never fights the player: it pauses while a camera pan is in flight and while
  the player is drag-panning.
* One moving unit owns the camera at a time. A different unit may only take
  over after `FOLLOW_SWITCH_COOLDOWN_MS` (3 s) of camera quiet from the previous
  unit, so two simultaneous GoTo marches cannot tug the view back and forth —
  the player gets a moment to register the first unit's move before the camera
  turns to the second.
* Like the black-screen rule, the follow lives at the UI call site — engine/AI
  paths never move the human's camera.

== Benefits

. *Centralized Logic* - All Go To functionality in one place
. *Easier Debugging* - Single source of truth for Go To operations
. *Reusability* - Can be used by AI, UI, and automation systems
. *Better Testing* - Isolated class can be unit tested
. *Maintainability* - Changes to Go To behavior only need to be made in one place
. *Animation Support* - Built-in support for animated multi-step movement

== Usage Example

[source,typescript]
----
// In GameCanvas or other components
const goToManager = (gameEngine as any)?.goToManager;

// Calculate path
const pathResult = goToManager.calculatePath(
  unit,
  targetCol,
  targetRow,
  getTileAt,
  mapWidth,
  mapHeight
);

if (pathResult.success) {
  // Set the path
  goToManager.setUnitPath(unit.id, pathResult.path);

  // Execute with animation
  await goToManager.executePathWithAnimation(
    unit.id,
    300, // delay between steps in ms
    (remainingSteps) => {
      // Update UI after each step
      console.log(`${remainingSteps} steps remaining`);
    }
  );
}
----
