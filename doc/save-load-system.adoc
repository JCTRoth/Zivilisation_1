This document describes the Save/Load game system and the Diplomacy Report leader portrait rendering implemented in Civilization I Browser Game.

== Save / Load System

The game supports saving and loading the complete game state. Save files are downloaded to disk as `.json` files, and loading opens a file picker dialog to select a previously saved file. The functionality is accessible from the **Game Menu** (opened via the GAME button in the top menu bar).

=== Architecture

The Save/Load system follows a two-tier architecture:

1. **Game Engine Layer** (`src/game/engine/GameEngine.ts`)::
   Handles serialization and deserialization of the full game state to/from JSON. Uses `localStorage` as an intermediary staging area.

2. **UI Layer** (`src/components/ui/GameModals.tsx`)::
   Provides the user-facing Save/Load buttons, file download trigger, and file picker dialog in the Game Menu modal.

=== Save Game (File Download)

When the user clicks **Save Game**, the following flow occurs:

. `handleSaveGame()` calls `gameEngine.saveGame()` which serializes the complete game state to JSON and writes it to `localStorage` under the key `civ1_savegame`.
. The JSON blob is read back from `localStorage`.
. A file download is triggered via `DomUtils.downloadTextFile()` — the browser prompts the user to save a `.json` file.
. The filename follows the pattern `civ1-save-turn-{turn}.json` (e.g., `civ1-save-turn-42.json`).

The serialized save data includes:

* `version` — Save format version (currently `5`; versions `1`–`5` load)
* `timestamp` — When the save was created
* `gameSettings` — Game configuration (number of civilizations, map size, difficulty, etc.)
* `currentTurn` — Current turn number
* `currentYear` — Current in-game year
* `activePlayer` — ID of the active player
* `map` — Full map state (tiles, terrain, improvements, visibility, explored status)
* `units` — All units with their properties (type, position, health, moves, orders, etc.)
* `cities` — All cities with production, population, buildings, build queue, etc.
* `civilizations` — All civilizations with resources, technologies, diplomatic state,
  and (in v5) the denormalised `teamId`, etc.
* `technologies` — Technology tree state
* `gameSettings.fixedAlliances` — Whether the game uses fixed alliances (v5)
* `gameSettings.teamAssignments` — Slot-indexed team indices (v5)

On success, a notification *"Game saved to civ1-save-turn-{turn}.json"* is shown. On failure, appropriate error notifications are displayed.

=== Load Game (File Picker)

When the user clicks **Load Game**, the following flow occurs:

. `handleLoadGame()` creates a hidden `<input type="file" accept=".json">` element and programmatically clicks it.
. The browser's native file picker dialog opens, filtered to `.json` files.
. When the user selects a file, its content is read via `file.text()`.
. The JSON is validated — must have `version` in `1..5`.
. The valid JSON is stored in `localStorage` under `civ1_savegame`.
. `gameEngine.loadGame()` is called, which:
.. Reads the JSON from `localStorage`
.. Restores all engine properties (currentTurn, currentYear, activePlayer, map, units, cities, civilizations, technologies)
.. Recreates the `SquareGrid` pathfinding grid
.. Re-initializes subsystems (`playerStorage`, `scoutMemory`, `diplomacyManager`, `teamManager`, `victoryManager`)
.. Rebuilds fixed-alliance membership from `gameSettings.teamAssignments`, then
   reapplies `DiplomacyManager.applyTeamInvariants()` *after* the relations are
   restored, so a stale teammate war in the save is repaired to an alliance
.. Rebuilds the unit turn queue
.. Syncs everything to the Zustand store via `storeActions`
. A final store sync is performed in the UI layer to ensure all views are updated.
. Fog of war visibility is recalculated via `actions.updateVisibility()`.

If the user cancels the file picker, the Game Menu modal simply closes without any action.

On success, a notification *"Game loaded from {filename}"* is shown.

=== Keyboard Shortcuts

The following keyboard shortcuts are available (documented in the Help modal):

* `Ctrl+S` — Save game
* `Ctrl+L` — Load game

These shortcuts are handled by the game's keyboard event router (see `UseGameEngine.ts`).

=== Save File Format

Save files are plain JSON with the following structure:

[source,json]
----
{
  "version": 5,
  "timestamp": 1717539200000,
  "gameSettings": {
    "fixedAlliances": true,
    "teamAssignments": [0, 0, 1],
    ...
  },
  "currentTurn": 42,
  "currentYear": -3200,
  "activePlayer": 0,
  "map": {
    "width": 50,
    "height": 40,
    "tiles": [ ... ],
    "visibility": [ ... ],
    "revealed": [ ... ]
  },
  "units": [ ... ],
  "cities": [ ... ],
  "civilizations": [ { "id": 0, "teamId": 0, ... }, ... ],
  "technologies": [ ... ]
}
----

=== Save format versions

[cols="1,3", options="header"]
|===
|Version |Changes

|1
|Initial format.

|2–4
|Earlier diplomacy/economy additions. No team fields.

|5
|Fixed alliances: `gameSettings.fixedAlliances`,
`gameSettings.teamAssignments` and `civilizations[].teamId`.
|===

Versions 1–4 load as free-for-all. A version-5 save with
`fixedAlliances: false` (or an invalid team assignment) also loads as
free-for-all. See link:FIXED_ALLIANCES.adoc[Fixed Alliances].

=== Limitations

* Only one save can exist in `localStorage` at a time (the `civ1_savegame` key is overwritten on each save). However, since saves are also downloaded as files, users can keep multiple save files on disk by renaming them.
* Save format version `5` is the current format; versions `1`–`4` load with
  free-for-all defaults. A save written by a *newer* format is rejected.
* No cloud save support (only local file download/upload).
* Large maps with many units may produce save files of several megabytes.

== Diplomacy Report — Leader Portraits

The Diplomacy Report (`diplomacy-report` dialog) and the Diplomacy negotiation modal (`diplomacy` dialog) display leader portraits for each civilization.

=== Architecture

Leader portraits are rendered by the `LeaderPortrait` React component (`src/components/ui/LeaderPortrait.tsx`).

The component supports two rendering modes:

1. **Image mode** (preferred):::
   If a `leaderName` prop is provided and a matching JPG file exists in `src/assets/leader/`, the component renders an `<img>` element pointing to the imported image asset. This is the primary rendering path.

2. **Procedural SVG mode** (fallback):::
   If no `leaderName` prop is provided (or no matching image is found), the component falls back to generating an SVG portrait procedurally from the `LeaderPortraitConfig` data defined in `src/data/LeaderPortraits.ts`.

Images are imported in `LeaderPortrait.tsx` via Vite's static asset import:

[source,typescript]
----
import leader_Alexander_the_Great from '@/assets/leader/Alexander_the_Great.jpg';
import leader_Elizabeth_I from '@/assets/leader/Elizabeth_I.jpg';
// ... etc.

const LEADER_IMAGES: Record<string, string> = {
  'Alexander the Great': leader_Alexander_the_Great,
  'Elizabeth I': leader_Elizabeth_I,
  // ... etc.
};
----

=== How It Works

When rendering a leader portrait:

1. The caller (e.g., `GameModals.tsx`) looks up the leader name from the civilization data (e.g., `civ.leader` or `civ.leaderName`)
2. It finds the matching `LeaderPortraitConfig` from `LEADER_PORTRAITS` in `src/data/LeaderPortraits.ts`
3. It passes `config`, `mood`, `size`, and `leaderName` props to the `LeaderPortrait` component
4. The component checks if `leaderName` matches a key in `LEADER_IMAGES` — if so, it renders the JPG image; otherwise it renders the procedural SVG

The `leaderName` prop is the key that activates image mode. Without it, the component defaults to SVG rendering. Both the Diplomacy Report and the main Diplomacy modal now pass this prop.

=== Mood-Based Visual Feedback

The portrait frame and background reflect the AI's attitude:

* **Friendly** — Green glow (`#1a2e1a` background, `#4caf50` border)
* **Neutral** — Blue-gray (`#1a1a2e` background, `#8b7355` border)
* **Annoyed** — Orange glow (`#2e2a1a` background, `#ff9800` border)
* **Hostile** — Red glow (`#2e1a1a` background, `#f44336` border)

This applies to both the image and SVG rendering modes.
