= K3s Completion Plan
:revdate: 2026-11-20
:toc:
:toclevels: 3
:sectnums:

What the deployed stack does today, what is verified, what is missing, and a
phased plan to finish it.

Companion documents: link:CONTAINERS.adoc[Containers and Deployed Topologies]
(what each container is) and link:K3S_SETUP.adoc[K3s Setup] (how to run it).

== Verdict

The *functional* stack is complete and proven: a browser talks to a K3s-served
client, creates a room, two players join with signed tokens, a command
executes on one replica, the result reaches the other client, and the state is
in Postgres. The HPA scales under load, readiness is real, and the event bus
works across replicas.

The *operational* stack is not production-ready. Two defects are outright
broken (backups, PWA installability in the deployed image), and several
production concerns are unaddressed (no registry, no hardening, no monitoring,
single Postgres, self-signed TLS).

[cols="1,1,3"]
|===
|Area |State |Evidence

|Client + server + Postgres on K3s
|*Works*
|2 nodes, 2 web replicas, 1 Postgres StatefulSet, and the server at the HPA minimum of 2 (4 were observed during a load test) — `kubectl get pods -o wide`

|Runtime config injection
|*Works*
|`window.__CIV1_CONFIG__.gameServer` asserted by the e2e suite

|Commands across replicas
|*Works*
|e2e: seat 0 `SET_RATES` → seat 1 `/state`; `LISTEN`/`NOTIFY` fan-out

|Readiness / liveness
|*Works*
|`/ready` 200, `postgres` gated by `pg_isready`, init container waits

|Autoscaling
|*Works (observed)*
|HPA 2–6 at 60% CPU; 4 replicas were running during a load test, back to 2 at rest

|Metrics endpoint
|*Works*
|`civ1_commands_total`, `civ1_events_total`, `civ1_rooms`, …

|Structured logs
|*Works*
|JSON lines with `workerId`, `roomId`, `commandSeq`

|TLS ingress
|*Works (self-signed)*
|`https://civ1.local:30443/api/health` returns the room list

|Backups
|*Broken*
|`pg_dump: could not translate host name "civ1-postgres"` (network policy)

|PWA installability in the deployed image
|*Broken*
|`/manifest.webmanifest` served as `application/octet-stream`; `sw.js` has no cache header — the image predates the nginx fix

|Image supply chain
|*Missing*
|`:local` tags imported by hand; `imagePullPolicy: IfNotPresent`

|Container hardening
|*Missing*
|No `securityContext`, runs as root, no PSA labels
|===

=== How this was verified

The statements above were checked against a live cluster
(`scripts/setup-k3s-test.sh`, K3s v1.31.4, two nodes) on 2026-11-20:

[source,bash]
----
kubectl get nodes -o wide                  # 2 Ready
kubectl -n civ1 get deploy,sts,svc,hpa,cronjob
kubectl -n civ1 get pods -o wide           # 4 server, 2 web, 1 postgres
curl -k --resolve civ1.local:30443:127.0.0.1 https://civ1.local:30443/api/health
curl http://localhost:31787/metrics | head
kubectl -n civ1 create job --from=cronjob/civ1-pg-backup backup-probe
kubectl -n civ1 logs job/backup-probe      # DNS error — the backup is broken
kubectl -n civ1 exec <web-pod> -- cat /etc/nginx/conf.d/default.conf   # old config
----

== Gap register

=== P0 — broken or unsafe to ship

[cols="1,3,2,4"]
|===
|# |Gap |Consequence

|P0-1
|*The deployed web image predates the PWA nginx fix.* `kubectl exec <web-pod> -- cat /etc/nginx/conf.d/default.conf` shows only the old `location /assets/` and SPA fallback. The manifest is served as `application/octet-stream` and `sw.js` has no cache header.
|Browsers may refuse to install the PWA; a future worker can be cached unpredictably. The whole offline feature is unproven in the deployed stack.

|P0-2
|*The backup CronJob cannot reach Postgres.* The namespace has a default-deny egress policy; no policy matches the job pod, so DNS fails. Reproduced: `pg_dump: error: could not translate host name "civ1-postgres" to address: Try again`.
|There are no backups. A lost PVC loses every room.

|P0-3
|*No image registry, no immutable tags.* Images are `:local`, imported with `docker save | ctr import`, and referenced with `imagePullPolicy: IfNotPresent`.
|A node silently keeps an old image (this is exactly how P0-1 survived); a real cluster cannot pull at all; there is no audit trail of what is deployed.

|P0-4
|*`GAME_SERVER_URL` is hardcoded* to `http://localhost:30787` in `k8s/web.yaml` and patched by the setup script.
|The manifest is not deployable as written; the two supported modes (NodePort vs ingress) need different values and there is no declarative switch.
|===

=== P1 — production readiness

[cols="1,3,2"]
|===
|# |Gap |Consequence

|P1-1
|*No kustomize overlays.* One flat `k8s/` mixes the test cluster, the NodePort mode and the production intent.
|Every environment edits the same files by hand.

|P1-2
|*CORS is `access-control-allow-origin: *`* on every response.
|Unnecessary in ingress mode and wider than needed in NodePort mode. Should be a `CORS_ORIGIN` setting.

|P1-3
|*No PodDisruptionBudget; the web Deployment has no rolling strategy.*
|A node drain can take both web replicas down and, with the default 25% surge, briefly serve less than the intended capacity.

|P1-4
|*No `securityContext`* — both app containers run as root with default capabilities; the namespace has no Pod Security Admission labels.
|A container escape is root on the node. PSA `restricted` is not even attempted.

|P1-5
|*No cert-manager / real TLS.* Self-signed `civ1-tls`, 365 days, no renewal, `/etc/hosts` required.
|Installed PWAs require a trusted certificate; a browser warning blocks installation.

|P1-6
|*Postgres is a single StatefulSet* with a 2 Gi PVC and no replication.
|A node or disk failure is a full outage. Acceptable for a hobby deployment if documented; not for “production”.

|P1-7
|*Backups have no retention and no off-cluster copy*, and no restore has ever been tested.
|The PVC fills up, and the only copy of the data is on the same disk as the data.

|P1-8
|*`/health` returns a per-replica room list* (verified: two calls through one Service returned different sets).
|Operators read it as a cluster inventory. It is a liveness signal only.
|===

=== P2 — operability

[cols="1,3,2"]
|===
|# |Gap |Consequence

|P2-1
|*No Prometheus/Grafana.* The scrape annotations exist; nothing scrapes them.
|Metrics are only visible if you `curl` them by hand.

|P2-2
|*No alerts.* No rule for “no ready replicas”, “5xx rate”, “Postgres down”, “backup failed”.
|Failures are discovered by players.

|P2-3
|*No CI job for images or the deployed stack.* `tests.yml` runs unit tests; no workflow builds the Dockerfiles or runs the compose/K3s smoke tests.
|P0-1 (a stale image) cannot be caught by CI because CI never builds the image.

|P2-4
|*No `scripts/teardown-k3s-test.sh`.* The setup script leaves containers, a port-forward and `/tmp` artefacts behind.
|Repeated local runs accumulate state and confuse `ss`/`docker ps`.

|P2-5
|*The K3s e2e writes screenshots to `~/Desktop` by default.*
|Surprising outside a desktop session; CI needs `CIV1_SCREENSHOTS`.

|P2-6
|*No resource sizing data.* Server limits are `1000m`/`1Gi`; a 180×90 map with 7 AIs was never profiled against them.
|Throttling or OOM in a long game, discovered late.

|P2-7
|*The WebSocket transport is deployed but unused by the client.* `/ws` is routed, port 8788 is published, `civ1-web-egress` does not even allow it.
|Dead surface area, and a misleading security policy. Either the client uses WS or the deployment drops it.

|P2-8
|*The server image runs TypeScript through `tsx`* (279 MB, 107 MB of `node_modules`).
|Slower start-up and a larger attack surface than a compiled image.

|P2-9
|*No log shipping.* Logs are JSON on stdout, but nothing collects them.
|`kubectl logs` is the only history, and pods are short-lived.

|P2-10
|*No image scanning / SBOM.*
|Vulnerable base images go unnoticed.

|P2-11
|*`pg_isready -U civ1 -d civ1` is hardcoded* in the Postgres readiness probe and in the server's `wait-for-db` init container.
|Changing `POSTGRES_USER`/`POSTGRES_DB` in the secret makes every pod fail readiness with a confusing error.
|===

== Phased plan

Each phase is independently shippable and ends with a verifiable acceptance
test. Effort is in engineer-days for one person already familiar with the
stack.

=== Phase 0 — Ship what already works (0.5 d)

*Objective:* the current code, correctly deployed.

|===
|Task |Detail

|0.1 Rebuild the images
|`docker build -f packages/web/Dockerfile -t civ1browser-web:local .` and the server equivalent. The shipped web image must contain the current `nginx.conf`.

|0.2 Redeploy into K3s
|`docker save | ctr import` on both nodes, then `kubectl -n civ1 rollout restart deploy/civ1-web`.

|0.3 Verify the PWA in the cluster
|`curl -sI http://localhost:31080/sw.js` → `Cache-Control: no-cache`; `/manifest.webmanifest` → `application/manifest+json`; then install the app in a browser and load it offline.
|===

*Acceptance:* the deployed web pods serve the fixed nginx config and the
installed PWA launches with the network off.

=== Phase 1 — Fix the blockers (1–2 d)

|===
|Task |Detail

|1.1 Backup network policy
|Add a policy that selects the backup job's pods (give the pod template a label, e.g. `app: civ1-backup`) allowing egress to `civ1-postgres:5432` and DNS to `kube-system:53`.

|1.2 Prove the backup
|`kubectl create job --from=cronjob/civ1-pg-backup backup-probe` must succeed, `ls /backups` must show a `.dump`, and `pg_restore --list` must read it.

|1.3 Registry and immutable tags
|Build and push `ghcr.io/<org>/civ1-server:<git-sha>` and `civ1-web:<git-sha>`. Reference the digest in the manifests. Switch `imagePullPolicy` to `Always` (or keep `IfNotPresent` *with* digests).

|1.4 Image pull secret
|Document `imagePullSecrets` for a private registry.
|===

*Acceptance:* a scraped backup exists; the cluster runs images referenced by
digest; changing the tag in one place is the only way to deploy.

=== Phase 2 — One manifest source (1–2 d)

|===
|Task |Detail

|2.1 Kustomize base + overlays
|`k8s/base/` (namespace, postgres, server, web, hpa, netpol, ingress) and `k8s/overlays/{local-nodeport,local-ingress,prod}`. The `local-*` overlays patch `GAME_SERVER_URL`; `prod` sets the real host and `/api`.

|2.2 Delete the patch from the setup script
|`scripts/setup-k3s-test.sh` applies `k8s/overlays/local-nodeport` instead of patching the ConfigMap.

|2.3 Document the mode switch
|A single table in `doc/CONTAINERS.adoc` (already present) and a line in `K3S_SETUP.adoc` pointing at the overlay.

|2.4 Validate with `kubectl kustomize`
|A test asserts each overlay renders, and that no overlay contains a literal secret.
|===

*Acceptance:* `kubectl apply -k k8s/overlays/local-nodeport` and
`…/local-ingress` both work with no manual patching; `grep -r "<your-host>"
k8s/overlays/prod` is the only place a real host appears.

=== Phase 3 — Security hardening (2–3 d)

|===
|Task |Detail

|3.1 `securityContext`
|`runAsNonRoot: true`, `allowPrivilegeEscalation: false`, `capabilities.drop: [ALL]`, `readOnlyRootFilesystem: true` (nginx: `emptyDir` for `/var/cache/nginx` and `/var/run`; use `nginxinc/nginx-unprivileged`).

|3.2 Pod Security Admission
|Label the namespace `pod-security.kubernetes.io/enforce: restricted` in the `prod` overlay; keep `baseline` locally.

|3.3 CORS setting
|Add `CORS_ORIGIN` to the server (default: the current `*` for dev; the ingress host in prod). Reflection is not acceptable — use an explicit allow-list.

|3.4 Secret management
|Either sealed-secrets (simple, git-friendly) or external-secrets (Vault/cloud). No more imperative `kubectl create secret` in a runbook.

|3.5 Rotate every credential
|New `GAME_SERVER_SECRET` (invalidates outstanding seat tokens — document the consequence), new DB password, re-issue the TLS secret.
|===

*Acceptance:* `kubectl -n civ1 get pods` shows all pods passing the restricted
profile; a request from an unlisted origin is rejected; the two secrets exist
in git as sealed manifests only.

=== Phase 4 — Availability and data (3–5 d)

|===
|Task |Detail

|4.1 PodDisruptionBudgets
|`minAvailable: 1` for web and server; `maxUnavailable: 1` for web's rolling update.

|4.2 Postgres decision
|Two options, pick one and document it: (a) *managed* Postgres (RDS/Cloud SQL) — recommended for anything real; (b) *self-hosted HA* with Patroni or CloudNativePG. The single StatefulSet stays only for local/test.

|4.3 Backup retention + off-site
|Keep 7 daily / 4 weekly; stream the dump to object storage (S3/MinIO) instead of a local PVC. Add a `restore.sh` and a documented drill.

|4.4 Restore drill
|Restore the latest dump into a scratch namespace, start the server against it, and assert a room's save blob and RNG state load (`tests/` already proves the blob round-trip).

|4.5 PVC sizing
|Raise the data PVC above 2 Gi or make it a parameter; alert at 80% usage.
|===

*Acceptance:* draining a node keeps the game up; a restore from the latest
off-site dump serves a working room.

=== Phase 5 — Observability (2–3 d)

|===
|Task |Detail

|5.1 Prometheus + Grafana
|Either `kube-prometheus-stack` or a minimal Prometheus with the existing pod annotations. Add `ServiceMonitor`s for web and server.

|5.2 Dashboard
|`doc/dashboards/civ1.json` — commands/s, rejection ratio, event rate, rooms, saves, stream count, pod CPU/memory, HPA replicas.

|5.3 Alerts
|`NoReadyServer`, `PostgresDown`, `BackupJobFailed`, `HTTP5xxRate`, `RoomCountSpike`. Route to whatever the operator uses.

|5.4 Log collection
|Ship the JSON lines (Loki/Vector/Fluent Bit). Add `roomId` to every line the room emits (partially present today).

|5.5 Fix `/health`
|Keep it as a liveness signal and document that the room list is per-replica — or add `GET /rooms?all=true` that queries the shared store.
|===

*Acceptance:* a dashboard shows live traffic during the e2e run; killing
Postgres fires an alert; `kubectl logs` history survives a pod restart.

=== Phase 6 — CI/CD (2–3 d)

|===
|Task |Detail

|6.1 Image workflow
|`.github/workflows/images.yml` builds both Dockerfiles on every push, pushes `:sha` + `:latest` to GHCR, and records the digest.

|6.2 Compose smoke
|A job runs `docker compose up -d`, waits for `/health`, runs the multiplayer spec against compose, then tears down.

|6.3 K3s smoke (self-hosted runner or `k3d`)
|`scripts/setup-k3s-test.sh` + `npm run test:k3s` in CI. If a privileged Docker runner is unavailable, use `k3d` instead of the container-in-container cluster.

|6.4 Trivy / SBOM
|Scan both images; fail on `HIGH` with a fix available; publish an SBOM artefact.
|===

*Acceptance:* a red CI run blocks a release; the deployed digest in the
manifests always matches the one CI built.

=== Phase 7 — Tuning and the WebSocket decision (2 d)

|===
|Task |Detail

|7.1 Resource profiling
|Play a 180×90 map with 7 AIs; measure RSS and CPU per room; set requests/limits from data. Record the numbers here.

|7.2 Load test the HPA
|Fixed script: N rooms × M commands, watch replicas go 2→6 and back; assert no room is lost and reconnects use `?after=seq`.

|7.3 Decide the WebSocket transport
|Either the client uses `wsTransport` (update `civ1-web-egress` for 8788) or the deployment drops the `/ws` route and port. Document the decision.

|7.4 Probe credentials from the secret
|Make the `pg_isready` user/database in the readiness probe and the init container read from `civ1-db` instead of hardcoding `civ1`.
|===

*Acceptance:* documented sizing table; a recorded scale-up/scale-down curve;
one transport in the deployment, not two.

=== Phase 8 — Real TLS and DNS (1 d)

|===
|Task |Detail

|8.1 cert-manager
|Install cert-manager, a Let's Encrypt `ClusterIssuer`, and annotate the ingress. Keep the self-signed issuer for local.

|8.2 Real hostname
|Replace `civ1.local` in the `prod` overlay; remove the `/etc/hosts` and `--host-resolver-rules` workarounds from the docs (they stay for local).

|8.3 Verify installation
|Install the PWA over HTTPS from a real hostname in Chrome and Safari, and launch it offline.
|===

*Acceptance:* `https://<host>/` has a trusted certificate and the installed
PWA works offline on both browsers.

== Definition of done

The setup is “complete” when all of these are true:

. `kubectl -n civ1 get pods` shows every pod `Running` and passing the
  `restricted` Pod Security profile.
. The deployment references images by digest that CI built and pushed.
. `kubectl create job --from=cronjob/civ1-pg-backup` succeeds, and a restore
  from the latest dump has been performed at least once.
. Draining a node keeps the web and server available (`PodDisruptionBudget`).
. Postgres is either managed or an explicitly documented single-instance
  trade-off, with off-site backups.
. A dashboard shows commands, rooms, errors and replica count live; alerts
  fire for no-ready-replicas, Postgres down and a failed backup.
. HTTPS is trusted, and the PWA installs and launches offline from the real
  hostname.
. `npm run test:k3s` passes in CI against the deployed stack.
. `doc/CONTAINERS.adoc` and `doc/K3S_SETUP.adoc` match reality — the test
  cluster and the production overlay are the only differences.

== Out of scope (deliberately)

* Multi-region or geo-replication.
* Matchmaking, accounts or OAuth — seats are token links by design.
* A CDN for the 38 MB of game art (the service worker already caches it).
* Kubernetes-native databases beyond Postgres (Redis was considered and
  rejected: `LISTEN`/`NOTIFY` already covers cross-replica fan-out).
