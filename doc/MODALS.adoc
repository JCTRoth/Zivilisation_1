= Modals — every dialog, how it opens, and what protects it
:toc:
:toclevels: 2

This is the map of the dialog system: which of the three dialog mechanisms a
screen belongs to, exactly what opens it, what the player sees, which strings
and CSS classes the test suite latches onto, and which dialogs the game still
does not have.

Source paths and line numbers below are a snapshot of the working tree. The
UI is under active restyle, so treat the *structure* (dialog id, trigger, data
source) as the contract and the line numbers as approximate.

== Overview

=== Three systems, one shell

The app has three independent places that decide "a dialog is open". They do
not share a scheduler — only system A is visible to the engine's auto-end gate.

*A — store-driven `uiState.activeDialog`* :: The union type lives in
`types/game.ts` (~L636): `city | tech | diplomacy | game-menu | help | pause |
city-production | city-purchase | city-citizens | city-details | hex-details |
rates | government | statistics | wonders | village | upkeep-disbanded |
city-starved | city-disorder | trade-route-result | research-required |
auto-end-offer | wonder-completed | wonder-conflict | null`.
`actions.showDialog(name)` / `actions.hideDialog()` are plain reducers in
`src/stores/GameStore.ts` (L603, L633). Almost every renderer lives in
`src/components/ui/GameModals.tsx`, which subscribes to `uiState.activeDialog`
and mounts one component per id (the return block at L2181–L2217). A few ids
are opened through purpose-built actions instead of `showDialog` —
`showVillageResult`, `showUpkeepDisbanded`, `showCityStarved`,
`showCityDisorder`, `showTradeRouteResult`, `queueWonderDialog`,
`openDiplomacy`, `showIncomingDiplomacyOffer` (`GameStore.ts` L641–L750) — but
they all land on the same single `activeDialog` slot, so *only one store
dialog can be on screen at a time*.
+
Two engine-side gates read the id: `EngineEventHandlers.isDecisionScreenOpen`
(L1161) defers auto-end while anything but `game-menu` / `help` / `tech` /
`hex-details` is open, and `GameModals.NON_BLOCKING_DIALOGS` (L128) decides
whether closing that id re-runs the auto-end check (see
`doc/auto-end-turn.adoc`).

*B — local state in `src/App.tsx`* :: Plain `useState` booleans that never
touch the store: `showGameSetup` (L60), `showSettings` (L59),
`showEndTurnConfirm` (L61), `confirmNewGame` / `confirmQuit` (L62–L63), plus
`gameResult` (read from the store) driving `PauseScreen` and
`GameResultOverlay`. The `GameMenuSheet` (`activeMenu`, L56) and the DOM
`showToast` helper (L101) live here too. Because these are not `activeDialog`,
the engine cannot see them.

*C — canvas-local state in `src/components/game/GameCanvas.tsx`* :: `contextMenu`
(L139) drives the ORDERS unit menu, `stackModal` (L163) drives the unit-stack
picker. Both are rendered inside the canvas component (L3195, L3205) and are
dismissed by state reset, never by `hideDialog`. A third piece of state,
`onExamineHex`, points back into `App` — see the dead rows below.

*The shared shell* :: `src/components/ui/gamemodals/ModalShell.tsx` exports
`GameModal`, a react-bootstrap `Modal` wrapped in the house layout:

----
hero (artwork placeholder + eyebrow + title + lede)
  → .gm-content (scrolling sections)
  → .gm-actions (fixed action bar)
----
+
Styling comes from `src/styles/gameModalShell.css` (625 lines) and is
namespaced `.gm-*`: `.gm`, `.gm-modal`, `.gm-body`, `.gm-close`, `.gm-hero`
(with `.gm-hero--cover`), `.gm-art` / `.gm-art--lg` / `.gm-art--plain`,
`.gm-art-glyph`, `.gm-art-tag`, `.gm-eyebrow`, `.gm-title`, `.gm-lede`,
`.gm-content`, `.gm-section`, `.gm-section-title`, `.gm-prose`, `.gm-list`,
`.gm-kv-grid`, `.gm-kv`, `.gm-callout`, `.gm-note`, `.gm-chip`,
`.gm-stat-grid`, `.gm-stat`, `.gm-stat-value`, `.gm-stat-icon`,
`.gm-stat-label`, `.gm-actions`, `.gm-actions-spacer`.
+
Two props make every screen read as the same family:

* `tone` — `info | danger | success | gold | solemn | neutral`
  (`ModalTone`, `ModalShell.tsx` L10). The tone sets `--gm-accent` and
  `--gm-tint` on `.gm-body[data-tone=…]`
  (`gameModalShell.css` L62–L66), which drives the hero wash, the eyebrow and
  the section markers.
* `icon` / `artLabel` / `artSrc` / `artLayout` — the artwork slot renders a
  *striped placeholder with a caption naming the picture that belongs there*
  unless `artSrc` is passed. That is why most rows below say "placeholder":
  the hole is sized and styled, the picture is not painted yet.
+
Buttons inside a shell modal use the game-wide `.touch-btn` family from
`design-system.css` (`--primary`, `--success`, `--danger`, `--ghost`).

=== Non-modal feedback

* `NotificationCenter` (`src/components/ui/NotificationCenter.tsx`) renders the
  store's `uiState.notifications` queue as dismissible toasts
  (`.notification-center[role=status]`, `.notification-item--{type}`). Nearly
  every engine event that is not a modal lands here via
  `notify()` in `src/utils/NotificationUtils.ts`.
* `App.showToast()` (L101) is a *separate*, DOM-injected toast
  (`.app-toast`) used only for save / load / export feedback.
* Loading and error screens are plain full-page returns in `App.tsx`
  (L1249, L1278).

== Missing modals

Ranked by player value. Each entry: working title → trigger → what it shows →
why it matters. The "currently" notes come from
`src/utils/EngineEventHandlers.ts` and `src/game`; the event names are real
emissions, verified against the router's `switch`.

=== 1. Combat Report
* **Trigger:** `COMBAT_VICTORY` / `COMBAT_DEFEAT` / `CITY_ATTACKED` when the human owns a participant — today `onCombat` (L544) only pushes a toast through `notify()` plus a 0.8 s cloud animation.
* **Shows:** attacker vs defender with portraits, damage dealt/taken, who survived, casualties on both sides, veterancy XP earned, and for city assaults the wall strength before/after.
* **Why:** combat is the core feedback loop of the game and its result currently evaporates after three seconds in the toast stack. A player who looks away mid-animation never learns that a unit died.

=== 2. City Lost / City Taken (`CITY_CAPTURED`, `CITY_DESTROYED`, `CITY_JOINED`)
* **Trigger:** these three events are emitted (`GameEngine.ts` L3706, L3749, L3794, L3820, L4631, L5093) but *have no case in the router at all* — they fall through to `debugLog('Unhandled game engine event')`.
* **Shows:** capture vs raze, who now holds it, population carried over, garrison fate, and for a human city lost — a "your city has fallen" screen with a Go to City / counter-attack action.
* **Why:** losing a city is the single most consequential event in a Civ game and it is currently *silent*. `doc/CITY_CAPTURE.adoc` documents the mechanic; the UI documents nothing.

=== 3. War Declared / Peace Made (a real diplomacy notice)
* **Trigger:** `WAR_DECLARED`, `PEACE_MADE`, `ALLIANCE_BROKEN`, `CEASEFIRE_SIGNED`, `ALLIANCE_FORMED` — all toasts today (`onWarDeclared` L1438 and siblings).
* **Shows:** full-screen proclamation with both leaders, the casus belli, what the treaty changes for the player (borders closed, units at risk), and a "Open Diplomacy" action.
* **Why:** an AI declaring war on you is buried in a toast that auto-dismisses; the player may play several turns without noticing they are at war. Treaty expiry/anniversary has no event at all yet (`DiplomacyManager` has no expiry logic) and would need one first.

=== 4. Save / Load Feedback
* **Trigger:** `GAME_SAVED` (`GameEngine.ts` L6921) and `GAME_LOADED` (L7224) are emitted but unhandled. The menu path compensates with `App.showToast`; the `Ctrl+S` / `Ctrl+L` shortcuts (`App.tsx` L1195–L1206) give *no feedback at all*.
* **Shows:** a small shell-styled confirmation: file name, turn, timestamp, byte size; on load, "restored turn N, M cities, K units" or a clear failure reason.
* **Why:** the fastest way to lose a long game is not knowing whether the save landed.

=== 5. Unit Disband Confirmation
* **Trigger:** ORDERS ▸ Disband calls `gameEngine.disbandUnit(unit.id)` immediately (`GameCanvas.tsx` L2698) with only a "Unit X disbanded" toast afterwards.
* **Shows:** the existing `ConfirmDialog` component with tone `danger` — unit name, its type/rank, and the gold it will save.
* **Why:** it is irreversible and sits one right-click away from "Go to". The game already owns an accessible confirm dialog used for New Game and Quit; this is the same class of mistake.

=== 6. Production Completed
* **Trigger:** `UNIT_PRODUCED` / `UNIT_PURCHASED` / `BUILDING_COMPLETED` — currently `onUnitCreated` (L838) auto-selects the unit and toasts "X ready to move!".
* **Shows:** a compact shell modal: what finished, in which city, its stats, and a "Take command" / "Next item in queue" pair. Wonders already have their own screen (§ wonder-completed) — this is the ordinary-unit equivalent.
* **Why:** the auto-selection is a surprising camera jump when you are managing another front; a modal makes the interruption legible instead of mysterious.

=== 7. City Founded
* **Trigger:** `CITY_FOUNDED` → `onCityFounded` (L856), which toasts "X founded!" and silently selects the city.
* **Shows:** new city on a small map inset, its starting yields, and a first-production prompt (the idle-production prompt already exists for the *next* turn — this closes the gap at turn 0 of the city's life).
* **Why:** founding a city is the moment the empire's shape changes; it deserves more than a line in the toast stack.

=== 8. Population Growth & Border Expansion
* **Trigger:** *no event exists yet* — nothing in the emitted set corresponds to growth or a culture-border expansion. Needs a new `CITY_GROWTH` / `BORDER_EXPANDED` emission from the round processing.
* **Shows:** one-line celebratory card per city (population 4 → 5, new worked tile) — deliberately non-blocking, dismissible, or aggregated per turn.
* **Why:** growth is invisible today; players only notice it by reading the city screen. Border expansion changes what can be reached and is even easier to miss.

=== 9. Revolution Started / Government Change Completed
* **Trigger:** `startRevolution` (`GovernmentManager.ts` L257) sets `government = 'anarchy'` for `ANARCHY_TURNS`; no event, no screen. The Government modal only shows the anarchy banner while it happens to be open.
* **Shows:** "Revolution!" on start (rates fall to 0, N turns) and "New Charter Adopted" on completion, with the before/after tax and science caps.
* **Why:** anarchy silently zeroes three sliders; a player who opens the rates screen three turns later has no idea why income collapsed.

=== 10. End-of-Turn Recap
* **Trigger:** `TURN_END` / `TURN_PROCESSED` for the human, next to the existing auto-end recap toast (`App.tsx` L416).
* **Shows:** a dismissible per-turn digest: cities produced, growth, discoveries, gold delta, and anything the auto-resolver decided on the player's behalf.
* **Why:** the engine already *computes* this summary for auto-end; surfacing it for manual turns costs almost nothing and answers "what just happened to my turn?".

=== 11. Unit Upgraded
* **Trigger:** `UNIT_UPGRADED` (`TurnManager.ts` L1225) — emitted, unhandled.
* **Shows:** old type → new type, gold spent, and where the unit is.
* **Why:** silent auto-upgrades change unit stats under the player's hands.

=== 12. Road / Railroad / Irrigation Completed
* **Trigger:** `IMPROVEMENT_BUILT` → toast only (`onImprovementBuilt` L1050); `IMPROVEMENT_WORK_STARTED` and `POLLUTION_CLEANED` are unhandled.
* **Shows:** a small "work finished" card naming the tile, the yield delta gained, and the freed-up worker's next suggestion.
* **Why:** multi-turn worker jobs end with no acknowledgement, so it is unclear whether the unit is idle or still working.

=== 13. Tax Rate Consequences
* **Trigger:** `SET_RATES` command result — no dialog today; the Rates modal just closes.
* **Shows:** a projected confirmation: "Tax 40 / Science 50 / Luxury 10 → +12 gold, +17 beakers; below the cap for Despotism". Optionally a warning when a change will push a city into disorder next turn.
* **Why:** the sliders already compute the projection; showing it at the moment of commitment prevents the classic "I cut science by accident" regret.

=== 14. Barbarian Sighting
* **Trigger:** *no event exists* — village-barbarian results have a modal (`village`), but wandering barbarians spawning or entering sight do not.
* **Shows:** a border warning with the stack size, nearest city and a "Send a garrison" action.
* **Why:** barbarians are the early-game threat; a spawn on the edge of vision is easy to miss on a large map.

=== 15. Trade Route Lost / Route Ledger
* **Trigger:** no loss event exists; `TRADE_ROUTE_ESTABLISHED` has a modal but nothing removes routes today.
* **Shows:** which route died, why, and the gold per turn now missing; plus a "Routes" tab already half-built inside the city screen's Trade Routes tab.
* **Why:** the promised "+N gold every turn" silently stops when a city falls.

=== 16. Era Breakthrough
* **Trigger:** `TECH_RESEARCHED` already opens the research-complete modal; era change is derivable from the tech but not surfaced.
* **Shows:** "You enter the Industrial Era" with the new unit/building/wonder classes unlocked.
* **Why:** era is the game's largest structural beat and currently only changes colour in the tech tree.

=== 17. Pollution / Disease Notice
* **Trigger:** `POLLUTION_CLEANED` is emitted (`GameEngine.ts` L6477) but unhandled; pollution *appearing* has no event.
* **Shows:** a warning naming the polluted tile and its effect, with a "send a worker" action.
* **Why:** the rules already model pollution; the player cannot see it accumulate.
